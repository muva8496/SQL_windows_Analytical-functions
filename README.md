Quickmart Analytical Window Functions Lab (qm_windows_lab)

End-to-end SQL analytical engineering project applying PostgreSQL window functions (ROW_NUMBER, DENSE_RANK, LAG, LEAD, FIRST_VALUE, AVG, STDDEV_POP, SUM, and COUNT with explicit frame bounds) to a multi-branch East African supermarket dataset (qm-supermarket) across Kenya, Uganda, Tanzania, and Rwanda.

Rather than collapsing transaction records with standard GROUP BY aggregations, every pipeline in this repository preserves row-level operational context while computing partitioned rankings, moving averages, inter-visit intervals, statistical anomaly flags, branch leaderboards, and leakage-free machine learning features.

Tech Stack & Architecture

Database: PostgreSQL (Quickmart_SQLAlchemy / qm-supermarket schema)

Execution Layer: Python 3.11, SQLAlchemy, psycopg2, pandas, python-dotenv

Environment: Conda (qm_windows_env) + VS Code

Design Pattern: Modular CTE pipelines separating grain deduplication (transaction_id, (branch_id, sales_month), (loyalty_card_id, order_timestamp)) from window computations and NULLIF(..., 0) zero-variance guards.

Setup & Execution Workflow

1. Environment & Database Configuration

Activate the Conda environment and configure .env in the project root with your PostgreSQL connection parameters consumed by config/db.py:

conda activate qm_windows_env


Verify schema connectivity against the sales table (transaction_id, date, time, branch_id, branch_name, city, product_id, category, quantity, gross_amount_kshs, discount_kshs, net_sales_kshs, loyalty_card_id, cashier_id):

python -m scripts.inspect_schema


2. Running Any Analytical Session

Execute any SQL script via scripts/run_sql.py, preview top rows in the terminal, and export the full result set to outputs/:

python -m scripts.run_sql results/<script_name>.sql --save-csv <output_name>.csv --rows 30


Analytical Sessions & Key Findings

Session 1: Top SKUs per Branch (results/01_top_skus_by_branch.sql)

Window Mechanics: SUM(net_sales_kshs) aggregated at (branch_id, product_id) grain, followed by ROW_NUMBER() and DENSE_RANK() partitioned by branch_id ordered by revenue descending, filtered to Top 5 per store.

Business Value: Isolates branch-specific revenue drivers without losing tie visibility (DENSE_RANK vs. ROW_NUMBER), supporting localized shelf allocation and restocking priorities across stores.

Session 2: Daily Cumulative & 7-Day Rolling Sales Velocity (results/02_rolling_sales_velocity.sql)

Window Mechanics: Daily revenue and unit volume smoothed using SUM(...) OVER (ORDER BY date ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) and AVG(...) OVER (ORDER BY date ROWS BETWEEN 6 PRECEDING AND CURRENT ROW).

Business Value: Separates weekday/weekend noise from genuine demand inflection points and exposes loss-leader dynamics—days where unit volume spikes sharply while net revenue grows slower due to high-turnover, low-margin promotional staples.

Session 3: Loyalty Shopper Cadence & Cross-Branch Migration (results/03_customer_cadence_gaps.sql)

Scale: 331,301 deduplicated loyalty receipts.

Window Mechanics: Line items rolled up to receipt grain (loyalty_card_id, transaction_id, order_timestamp), sequenced with ROW_NUMBER(), and analyzed backward and forward with LAG(order_timestamp), LAG(receipt_net_sales_kshs), and LEAD(order_timestamp).

Key Findings from Output:

Cross-branch mobility: Loyalty members routinely shop across multiple locations rather than staying locked to a single home branch (e.g., LC100000 shopping at Quickmart Section 58 QM046 and later at Quickmart Embakasi QM012; LC100010 rotating across Umoja, Kilimani, Dagoretti Corner, and Kajiado Town).

High basket variance: Consecutive visit intervals range from under 4 days (3.96 days for LC100006) to nearly 300 days (297.52 days for LC100009), accompanied by basket swings exceeding ±3,800 KSH between trips.

Session 4: POS Cashier Discount Anomaly Detection (results/04_pos_cashier_anomalies.sql)

Scale: 829,193 cashier-attributed receipts.

Window Mechanics: Receipt-level discounts evaluated against each cashier's own historical baseline using expanding AVG(receipt_discount_kshs) and STDDEV_POP(receipt_discount_kshs) (ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW), inter-receipt checkout gaps via LAG(receipt_ts), and a rolling 10-receipt counter (ROWS BETWEEN 9 PRECEDING AND CURRENT ROW).

Key Findings from Output:

Statistical outliers (15.70σ to 19.23σ): Top-flagged transactions exhibit z-scores above 15.7 standard deviations over the cashier's own norm, with single-receipt discounts between 6,089.50 KSH and 15,930.00 KSH across branches in Nairobi (QM021-C05 Githurai 45, QM020-C02 Kahawa West, QM022-C14 Zimmerman), Eldoret (QM053-C11 Huruma), Nakuru (QM048-C01), Dar es Salaam (QM119-C01), and Kampala (QM101-C04).

Scale vs. rate distinction: High-value baskets (e.g., 146,665 KSH at Moi Avenue QM030-C09 and 172,405 KSH at Hurlingham QM033-C08) triggered 18.08σ and 16.27σ z-scores despite modest discount percentages (6.93% and 6.29%), demonstrating why both relative % and absolute KES z-scores belong in POS audit pipelines.

Session 5: Branch Month-over-Month Growth & Chain Share Leaderboard (results/05_branch_mom_growth.sql)

Scale: 1,872 branch-month records across the chain.

Window Mechanics: Monthly truncation (DATE_TRUNC('month', date)) paired with LAG(monthly_net_sales_kshs) for MoM growth, FIRST_VALUE(...) anchored across the full partition (UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING) for growth vs. initial baseline, SUM(...) OVER (PARTITION BY sales_month) for chain revenue share, and DENSE_RANK() for monthly store standings.

Key Findings from Output:

Rank mobility & seasonal surge: Quickmart Donholm (QM001) climbed from #12 in January 2025 (4.96M KSH, 1.33% chain share) to #2 in May (6.29M KSH, 1.52% share), before peaking at 8.17M KSH in December (+64.60% vs. January). Quickmart Buruburu (QM002) rose from #18 in January (4.45M KSH) to #5 in August (6.26M KSH, +18.51% MoM).

Operational applicability: Translates directly into an automated daily branch leaderboard (PARTITION BY date) giving store managers real-time chain rank and gap-to-#1 visibility.

Session 6: Leakage-Free ML Feature & Target Table (results/06_ml_feature_table.sql)

Scale: 130,327 model-ready repeat-visit observations (visit_number >= 2).

Window Mechanics: Strictly backward-looking rolling windows bounded at 1 PRECEDING (ROWS BETWEEN UNBOUNDED PRECEDING AND 1 PRECEDING and ROWS BETWEEN 3 PRECEDING AND 1 PRECEDING) combined with forward-looking LEAD(..., 1) targets.

Engineered Features & Targets:

Temporal & Basket Context: day_of_week, hour_of_day, is_weekend, line_items, total_units, current_spend_kshs, current_discount_pct.

Historical RFM & Behavioral Signals (Zero Leakage): customer_tenure_days, days_since_prev_visit, switched_branch_flag, prior_visit_count, prior_cumulative_spend_kshs, prev_1_spend_kshs, prev_2_spend_kshs, prior_3_avg_spend_kshs, prior_3_std_spend_kshs, prior_3_avg_units, and spend_vs_prior_3_avg_kshs.

Supervised Learning Targets: target_days_until_next_visit (time-to-next-purchase regression), target_next_spend_kshs (next-basket value regression), and target_returned_within_30d (binary 30-day retention classification).

Engineering Safeguards Built Into These Queries

Grain Discipline Before Windowing: Every multi-line transaction receipt is deduplicated in a primary CTE before applying LAG, LEAD, AVG, or STDDEV_POP, preventing multi-item receipts from skewing visit counts or discount baselines.

Division-by-Zero Protection: All percentage growth rates, discount shares, and z-score denominators wrap divisors in NULLIF(..., 0) so single-observation windows (STDDEV_POP = 0) cleanly yield NULL instead of aborting batch runs.
